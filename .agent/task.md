**Coverage: "int64 constant out of range" refusals in the default int64 mode.** The census stops about 30 of AIL's compiler modules on this refusal, e.g. hash constants like 0xcbf29ce484222325 or 1 << 64 masks.
- Since #284, ints are int64 by default and a source that statically needs big ints is refused, naming the line.
- Step 1: list the actual constants and how they are used, in docs/design/I64_CONSTANTS.md. Common patterns are masks (`x & 0xFFFFFFFFFFFFFFFF`), hash multipliers, and sentinels.
- Step 2, only for patterns whose result provably fits int64: build them without --exact-int, for example a mask applied to an int64 value. Everything else stays refused by name, with the --exact-int hint. Do not wrap silently anywhere.
- Compare stdout and exit code with CPython on probes.
- The generated C of the lab/compare tasks must be byte-identical.
- Add tests, run them plus test_ail_int64_default and test_ail_safetynet, run `python3 tools/update_manifest.py`, and commit.
