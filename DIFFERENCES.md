| C?-job-pre96-10242044-1 | class name shadowed by a parameter or local | `expr_Name` returned the module-level class value even when the activation had its own binding, so `def f(U): return U.m()` read the class object and both builds raised `AttributeError: 'type' object has no attribute 'm'` (CPython 42). | C?-job-pre97-10242045-1 | `str.split` / `rsplit` maxsplit | A constant maxsplit expression above int64 (for example `10**30`) compiled and then stopped at run time with `integer overflow`, where CPython raises `OverflowError`; `2**63 - 1` also overflowed on the intermediate power although the final limit fits. | C?-job-pre112-10242224-1 | dict keyed by a frozenset of tuples | The tuple pass lowered `frozenset({(1, "a"), (2, "b")})` used as a dict *lookup* key to its table class, but a table cannot be keyed by a set, so the dict stayed a plain object: `D[frozenset({(1, "a"), (2, "b")})]` raised `KeyError`, `... in D` printed False and `D.get(...)` returned None. | C?-job-pre116-10242227-1 | generator expressions | A generator expression saved as a value (assignment, argument, list item, attribute, dict value or return) was materialised eagerly on the general path. | C?-job-pre98-10242046-1 | collections.Counter missing keys | A Counter reached through a dict value, an argument, a list item, an attribute, a return value or an alias went through the generic dict getitem, so `table["k"]["y"] += 1` on a missing key raised `KeyError: 'y'`; CPython's `Counter.__missing__` returns 0 without inserting, then stores 1. | C?-job-pre113-10242225-1 | integer constant expressions | An all-int constant expression whose exact result fits int64 but whose intermediate does not (for example `(1 << 63) - 1` or `2**65 - 2**65`) was emitted as runtime checked operations and stopped with `integer overflow`. | C?-job-pre115-10242226-1 | zero division on the typed path and general `%` | The typed path's `pydiv`/`pymod` helpers called `ail_die`, so an uncaught `// 0` inside a callback (for example a `sorted` key) printed the bare trap text and exited 1 without the `ZeroDivisionError: ` prefix. The helpers now raise `AIL_EXC_ZERODIV` with CPython's messages; float `//`/`%`, float `/` and the general path's int `%` text are fixed too. | fixed |
| C?-job-pre120-10242313-1 | collections.Counter constructor/update | CPython 3.12's `Counter.update(mapping)` copies the mapping with `dict.update` when the counter is empty and only adds counts when it is not, so `Counter({"a": "x"})` keeps `"x"`; the general path added `0 + "x"` and raised `TypeError` (`Counter().update({"a": "x"})` did the same). Empty mapping updates now copy values; non-empty updates still add in CPython's operand order. Counter `repr` now orders string counts like `most_common`, and the operators' comparison with 0 names the operator CPython names. | fixed; `test_ail_pre120.py` |
