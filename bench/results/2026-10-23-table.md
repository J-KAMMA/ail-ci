## Where AIL is furthest behind C

1. **binary_cursor_records — 4.53x C (4.49x Rust).** AIL reads five fields through
   `BinaryCursor` accessors, each of which calls `remaining()` and performs its own bounds check
   before reading, from 65533-byte chunks. C and Rust decode whole records in a tight inlined
   loop over ~1 MiB buffers with native loads. The extra per-field calls and checks (five per
   13-byte record) dominate; the I/O volume is the same.
2. **csv_table — 2.50x C (2.26x Rust).** The one-pass `csv_table_group_scan` builds each selected
   field with repeated string concatenation (`field += ch`), then does a `slots.get(key)` dict
   lookup plus lookups in parallel count/total/min/max lists for every row. C/Rust parse in place
   over the whole buffer and update one open-addressing FNV table. Per-row allocation, string
   building and hashing are the likely overhead.
3. **json_query — 1.65x C (1.49x Rust).** `json_query_file` calls `data.decode("utf-8")` to
   validate UTF-8, which allocates a full string copy of the document, and then runs
   `json_pointer_scan_bytes(data)` over the original bytes. C and Rust validate, locate pointer
   targets and record spans in a single recursive pass without a second representation.
