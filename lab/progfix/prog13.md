## Change

`python/pkg-v12/optlib.py` now lowers a scalar Optional on a method as well as on a plain function
(int/float/bool/str/bytes parameter or result).  A method is accepted when its name is unique in the
program -- calls are rewritten by attribute name, so a second same-named method could bind the wrong
body -- and is refused by name when decorated.  Nested functions keep the old refusal.  A method
result used where only the pair would fit (for example a dict value) is refused by the same rule as a
top-level Optional function, so the program falls back whole instead of leaving a tuple in the general
build.  The struct
list-comprehension rule in `python/pkg-v12/pyfunc.py` now also produces `list[str]` when the element
is a str (`[p.name for p in ps]`), not only an int/float list.

`g12_026.py` therefore builds on the typed path; the programs that already built typed stay typed.
No int is wrapped: the Optional lowering only adds a present flag and an int64 value, and the
existing overflow rules are unchanged.

## Follow-ups (not attempted: each needs a new compiler feature, not a local fix)

1. `g12_036.py` -- module-level container of objects.  Exact message:
   `'_ail_en_EventKind_all' is a module-level list of non-numbers; only an int/float/str/bytes literal, or a numeric list or tuple, is accepted as a module constant.`
   The list is generated by the Enum lowering and read by the generated `_call` helper; the same
   module also has a `Random` object built at module scope.  A fix needs module-scope object
   constants/tables that preserve identity, not a table of literals.  After removing that table the
   next refusal is the generated dataclass `__lt__` whose bool return is a tuple comparison
   conditional (`NotImplemented` in the other arm), so the program needs more than one change.
2. `g19_036.py` -- module scope value built by a call.  Exact message:
   `'REFERENCE_TIME' is read before it is assigned`.
   `LAUNCH_TIME`/`REFERENCE_TIME` are annotated datetimes built by the datetime lowering and read in
   `main`.  Moving both assignments into `main` makes the whole prepared program compile on the typed
   path (verified in a temporary source), so the remaining work is a real feature: module-level
   object constants initialised once and shared by every reader.
